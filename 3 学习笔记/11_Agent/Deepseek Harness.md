| 预设模式       | 主要工作环境                                               |
| ---------- | ---------------------------------------------------- |
| **标准模式**   | 日常开发、文档、排错；能力完整，过程直观                                 |
| **PTC 模式** | 大量重复检索或多步工具组合；**用 TypeScript 程序批量组合工具调用，把多次往返压缩为一次** |
| **极简模式**   | 工具环境小，变量更少；检查运行时、试验插件、创建预设                           |
| **创造模式**   | 提供自省与创作能力                                            |


创造模式

```
我想创建一个个人自定义 Agent 预设，名称叫“项目维护助手”，建议 ID 使用 project-maintainer。

用途：维护小型代码项目。

行为要求：
1. 开始前阅读 README、项目结构和现有测试；
2. 超过两个步骤的任务先创建并维护计划；
3. 优先使用工作区信息，只有需要外部最新资料时才搜索网页；
4. 未经明确允许，不安装依赖、不删除文件、不修改工作区之外内容,请不要修改工作区之外文件；
5. 修改代码后运行相关测试；
6. 不允许通过删除测试绕过失败；
7. 最终报告改动文件、测试结果和剩余风险。
   


请先检查当前运行时和标准模式的插件组装，给出预设设计方案。先不要创建，等我确认。
```

```
请把设计拆成三层说明：
1. 预设需要挂载的插件与工具；
2. 写入 persona 或系统提示的行为约束；
3. 不能只靠提示词、必须由权限或沙箱保证的边界。
```


```
请先在内存中试验建议的插件组合，检查必要服务是否存在、插件依赖是否满足，以及是否能提供文件编辑、Shell、Plan、Skills 和按需网页搜索。不要卸载当前会话赖以运行的核心服务。
```


```
请根据确认后的方案创建 project-maintainer 预设。创建完成后：
1. 检查预设元数据和组装文件；
2. 验证预设能够被列表发现；
3. 不要修改内置预设；
4. 告诉我怎样在新会话中选择它。
```
