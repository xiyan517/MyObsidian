# Agentic：自主性与优势

> [!summary]
> **agentic** 描述程度，不争论「算不算 Agent」。自主性是谱系：低自主（步骤写死）→ 半自主（预置工具、LLM 选用）→ 高自主（LLM 定流程，甚至造工具）。三大优势：**效果**（常超过换代模型）、**并行**（相对人类更快）、**模块化**（工具/模型可换）。业务价值大量落在可控的低/半自主端。

来源：吴恩达 《Agentic AI》· P03 自主性程度 · P04 智能体 AI 的优势

---

## 1. 用 agentic，少争定义

| 旧习惯 | 问题 | 更好做法 |
| --- | --- | --- |
| 二元：是 / 不是 Agent | 定义战 | 用 **agentic** 作形容词 |
| 争论「够不够自主才算」 | 耽误构建 | 承认 **程度不同**，继续做系统 |

**自主性是连续谱，不是开关。**

---

## 2. 同一任务的两种写法

任务：写一篇关于黑洞的文章。

| | 低自主 | 高自主 |
| --- | --- | --- |
| **谁定流程** | 工程师写死线性步骤 | LLM 决定顺序与是否回环 |
| **工具** | 搜索、抓取等硬编码 | LLM 选工具、定次数；PDF 可再调「转文本」 |
| **LLM 角色** | 主要生成文本（检索词、正文） | 规划 + 选用工具 + 反思改进 |
| **流程示意** | 请求 → 生成检索词 → 搜索 → 抓页 → 写文 | 请求 → 选搜什么（网/新闻/arXiv）→ 调工具 → 写稿 → 反思 → 可能再抓 → 输出 |

核心差别：**谁决定下一步。**

---

## 3. 自主性谱系

| 档位 | 谁定步骤 | 工具 | LLM 干什么 |
| --- | --- | --- | --- |
| **低自主** | 工程师预先定死 | 调用常硬编码 | 主要生成文本 |
| **半自主** | 部分决策交给 LLM | 工具预定义，由 LLM **选用** | 选工具、做部分规划 |
| **高自主** | LLM 自定步骤序列 | 甚至可 **写新函数 / 造新工具** | 规划 + 选工具 + 可能造工具 |

速记：

- 低 ≈ 固定工作流 + LLM 填内容  
- 半 ≈ 预置工具箱 + LLM 路由  
- 高 ≈ LLM 当调度员，甚至扩工具  

选型：不是越自主越好。要稳定、可预期 → 偏左；开放探索、可接受不可控 → 偏右。企业里大量落地在 **低/半自主**。

---

## 4. 三大优势

最大卖点：许多 **以前做不好** 的任务，用 agentic workflow 变得可行。

### 4.1 效果：换工作流，常比换模型更猛

HumanEval（写代码）课例：

| 设置 | 大致正确率 |
| --- | --- |
| GPT-3.5 · 一次生成 | ~40% |
| GPT-4 · 一次生成 | ~67% |
| GPT-3.5 · agentic（写 → 反思 → 改） | 可冲到更高 |
| GPT-4 · 同样 agentic | 再上台阶 |

模型换代（3.5→4）已经很大，但把 **上一代** 包进 agentic，提升往往 **更大**。小模型同样受益。

→ **先设计工作流，别只等更强模型。**

### 4.2 并行：相对人类更快

写黑洞文时，可并行生成多组检索词、并行下载多页（如 9 页），再汇总写文。

| 对比 | 结论 |
| --- | --- |
| vs 单次 prompt | Agentic **更慢**（多轮多步） |
| vs 人类串行研究 | 可并行抓取，**往往更快** |

### 4.3 模块化：拼最佳组件

把链路拆成可替换积木，按步实验：

| 可换 | 例子 |
| --- | --- |
| 搜索引擎 | Google（SerpAPI）、Bing、DuckDuckGo、Tavily、You.com 等 |
| 搜索类型 | 网页 → 新闻（追最新 breakthrough） |
| 各步 LLM | 不同步骤可换不同模型/厂商，选该步最优 |

习惯：盯 **单个组件** 做增删替换，整条链不要绑死一家。

---

## 5. 带走

1. 谈 **agentic 程度**，不争「算不算 Agent」  
2. 差别在 **谁决定下一步**；按可控性需求选谱系位置  
3. 优势三件套：**效果 > 换代差距**、**并行快于人**、**组件可换**
